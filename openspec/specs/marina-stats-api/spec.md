## ADDED Requirements

### Requirement: Marina composition endpoint
The system SHALL provide `GET /marinas/{id}/composition` returning a `MarinaCompositionDto` that breaks down all slips for the marina by their current occupancy state. The query SHALL use LINQ `.Select()` projections only — no navigation-property entity loading. The endpoint SHALL be decorated with `[ResponseCache(Duration = 60)]`. The endpoint SHALL be in `MarinaStatsController`.

A slip's occupancy state is determined as:
- **annual / seasonal / monthly / transient** — has an active `SlipAssignment` with matching `AssignmentType`
- **listed** — no active assignment AND has at least one active `AvailabilityWindow`
- **maintenance** — `SlipStatus == Maintenance`
- **vacant** — none of the above

#### Scenario: Authenticated marina operator requests composition
- **WHEN** a user with a `Marina` membership for the marina calls `GET /marinas/{id}/composition`
- **THEN** the response is `200 OK` with a `MarinaCompositionDto` where `total == annual + seasonal + monthly + transient + listed + maintenance + vacant`

#### Scenario: Unauthorized request is rejected
- **WHEN** a user without membership for the marina calls `GET /marinas/{id}/composition`
- **THEN** the response is `403 Forbidden`

#### Scenario: Response is cached
- **WHEN** the same endpoint is called twice within 60 seconds
- **THEN** the second response is served from the output cache without hitting the database

### Requirement: Marina billing summary endpoint
The system SHALL provide `GET /marinas/{id}/billing-summary` returning a `BillingSummaryDto` that aggregates invoice and payment data for the marina. The query SHALL use LINQ `.Select()` projections only. The endpoint SHALL be decorated with `[ResponseCache(Duration = 60)]`. The endpoint SHALL be in `MarinaStatsController`.

`BillingSummaryDto` fields:
- `outstandingAmount` — sum of `(amount - paid)` for invoices with status `Sent | DueSoon | Overdue | Partial`
- `outstandingCount` — count of those invoices
- `overdueAmount` — sum of `(amount - paid)` for `Overdue` invoices
- `overdueCount` — count of overdue invoices
- `oldestOverdueDays` — days since `dueDate` for the oldest overdue invoice (0 if none)
- `mtdCollected` — sum of payment amounts recorded in the current calendar month
- `lastMonthCollected` — sum of payment amounts recorded in the previous calendar month
- `agingBuckets` — `{ current, days1to30, days31to60, days60plus }` outstanding amounts bucketed by days past due

#### Scenario: Authenticated operator requests billing summary
- **WHEN** a marina operator calls `GET /marinas/{id}/billing-summary`
- **THEN** the response is `200 OK` with a correctly computed `BillingSummaryDto`

#### Scenario: Marina with no invoices returns zero summary
- **WHEN** the marina has no invoices
- **THEN** all numeric fields in the response are `0`

#### Scenario: Unauthorized request is rejected
- **WHEN** a user without marina membership calls `GET /marinas/{id}/billing-summary`
- **THEN** the response is `403 Forbidden`

### Requirement: API type regeneration after backend additions
After `MarinaStatsController` is added, the TypeScript API schema SHALL be regenerated by running `npm run generate-api` with the API running. The generated `schema.d.ts` SHALL NOT be manually edited. Typed wrapper functions for both endpoints SHALL be added to `src/MyMarina.Web/src/api/api.ts`.

#### Scenario: Wrapper functions are present after regeneration
- **WHEN** `npm run generate-api` has been run and `api.ts` updated
- **THEN** `getMarinaComposition(marinaId)` and `getBillingSummary(marinaId)` are importable from `@/api/api`
